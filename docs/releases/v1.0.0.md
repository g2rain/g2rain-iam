# g2rain-iam v1.0.0

## 首次 GHCR 发布准备

`g2rain-iam` 是 G2rain 平台中的统一身份入口、授权服务与 Token 中心，提供登录、浏览器会话、授权码、Token 签发/刷新/交换、JWT/JOSE/DPoP 密钥编排，以及钉钉、企业微信等 IdP 接入编排。它不拥有 Passport、用户、组织或应用主数据；Gateway 负责入口转发和业务请求校验，领域服务负责最终领域授权。它不是 G2rain 平台全部能力的交付物。

G2rain 的现有 SaaS 基座、知识库、智能体平台及应用开发/部署能力均已开源；商业化能力仍处于规划。该平台状态不应被归因于 IAM 单一组件。

## 版本、构建与运行

- 项目版本事实源：根 `pom.xml` 的 `<version>1.0.0</version>`；根 POM 的 parent 为 Spring Boot `4.1.2`，依赖管理的 Spring Cloud 为 `2025.1.4`。
- 要求：JDK 25、Maven 3.9+；运行还依赖 Redis、Nacos、g2rain-basis API 和已配置的外部 IdP（按实际使用场景）。
- 本地 Jar 构建：`mvn clean package`；本地测试：`mvn test`；本地容器构建：`mvn compile jib:dockerBuild`。这些不等同于 CI、推送、匿名拉取或实际部署验证。
- 镜像配置事实源：根 POM 的 Jib 插件。基础镜像为 `eclipse-temurin:25.0.4.1_1-jre`，入口为 `com.g2rain.iam.Application`，默认服务和暴露端口均为 `8082`。Dockerfile 与上述运行时参数对齐，但 GHCR 发布统一使用 Jib。

## GHCR 与发布顺序

- 镜像：`ghcr.io/g2rain/g2rain-iam`。
- 标签：推送 `v1.0.0` 后发布 `1.0.0` 与 `sha-<完整提交 SHA>`；不更新或声明 `latest`。
- OCI 元数据：`org.opencontainers.image.source`、`licenses=Apache-2.0`、title、version 和 description。
- 工作流仅监听 tag push，并严格接受 `vX.Y.Z`。它确认 tag 提交已进入 `origin/main`、本文件在 tag 内同名且非空，并核对 Maven 项目版本后，执行 `mvn clean verify`，使用 `GITHUB_TOKEN` 登录 GHCR 并以 Jib 推送两个标签。工作流不创建 GitHub Release、不部署服务。
- 发布改动、工作流和本说明应先合入 `main`；随后在该已验证提交创建并推送 `v1.0.0` tag。不要在功能分支直接打发布 tag。

首次成功推送后，维护者须到 GitHub Packages 的 **Package settings → Change visibility → Public** 将包公开；若组织管理员禁止变更，请联系管理员。已有包遇到 `denied` 时，先检查 **Package settings → Actions access** 是否授予本仓库写权限以及组织 Packages 策略，不能只凭 `packages: write` 假定授权充分。

## 镜像内容与安全

Jib 将 Maven 编译产物及运行时依赖分层写入镜像；最终 Jar 包含 `src/main/resources` 的页面模板、banner、日志配置和 `application.yml`，不复制整个 Git 工作区。仓库没有 `.dockerignore`，且 `.dockerignore` 也不是敏感信息治理边界。

已跟踪的 `src/main/resources/application.yml` 会进入镜像，其中含开发默认 Nacos 地址、用户名/密码和默认 `BASE_URL`，因此应视为生产发布风险。生产密钥和凭据（Token 私钥、IdP Secret、回调 Token/AES Key、凭据加密 Key、生产 Nacos 凭据）必须从 Nacos、Secret 管理系统或部署环境变量注入，不得写入镜像、Git、日志或测试快照。维护者需在生产发布前审核这些默认值。

## 已知限制与验证状态

- 当前容器运行本身尚未替代 Redis、Nacos、Basis、Gateway、真实 IdP 或生产密钥配置；实际部署后仍需验证 health、登录、授权、Token、注销和真实 IdP 回调。
- DPoP `jti` 跨请求重放缓存、可信代理下完整外部 `htu` 绑定等已知偏差仍见 `docs/architecture/deviations.md`。
- 本次发布准备已通过 POM XML 解析与版本/镜像引用定向搜索。标准 `mvn test` 已执行但在 Enforcer 的 `RequireUpperBoundDeps` 阶段失败：`g2rain-common:1.0.9` 带入 `swagger-annotations-jakarta:2.2.46`，而 `springdoc-openapi:3.2.0` 要求 `2.2.55`；因此测试没有开始。本次未变更依赖版本。为定位是否存在第二个阻塞点，另以 `-Denforcer.skip=true` 重试，编译在 `TokenService.java` 的类型不兼容及缺少 `TokenJWTPayload#getEntryId()` 时失败；该源码/依赖不兼容也未在本次镜像发布范围内修改。Docker Desktop Linux daemon 不可用，故 Jib 本地镜像构建、层内容和容器运行均未验证。CI 的 `mvn clean verify` 与本地检查范围不同，首次 tag 运行的 GHCR 权限和双标签推送也尚未验证。
